# 人物设定与开篇状态的交付协议

`bible` 和 `ledger_in` 是 JSON 中两个独立的 Markdown 字符串。候选比较与选择理由放在 adaptation、differentiation、hooks 或 reason，不用候选散文代替这两个实际交付字段。

## bible 的机器可读结构

章节标题和表头必须使用下面的英文标识，行内容使用中文。Characters 必须是表格，不能只是姓名开头的段落或项目符号。每个角色一行，name 为本剧使用的唯一名字；episodes.characters 必须与这里或 Extras、Voices 中的名字一致。别名放在 source name 或描述里，不把同一个人拆成多行。

```markdown
## Characters
| name | role | look | voice | source name |
| --- | --- | --- | --- | --- |
| 本剧角色名 | 主角或配角职责 | 稳定外观及原文未明之处 | 音色、年龄感与说话特点 | 对应原文名字或别名 |

## Locations
| name | look |
| --- | --- |
| 本剧地点名 | 固定形制、主要入口及已知空间关系 |

## Props
| name | look |
| --- | --- |
| 剧情道具名 | 稳定外观与用途 |

## Voices
| speaker | voice profile |
| --- | --- |
| 实际需要的画外声音名 | 音色与表达方式 |

## Setting
稳定世界规则与信息可见范围。
```

上表行是格式占位，不是故事内容，不得原样复制。角色的 name、role、look、voice、source name 均需非空；原文未给出的外观和音色，可写清必要设计或待定项，不伪称原文事实。episodes.locations 必须在 Locations 中逐项登记。Props、Voices、Extras、UI 只按实际需要添加；Extras 可列群演名字，UI 使用 name、look 表格。单元格内不放竖线或换行，以免破坏列结构。

设定表记录身份与稳定特征，不把后续伤愈、获利、亲近、持有物转移等进展写成角色当前状态。人物不同阶段的变化由相应剧本和分集状态承接。

## ledger_in 只描述所选开篇之前的状态

先明确所选开篇的时间切点，记录这一刻各人的位置、伤势、持有物、关系、已知与未知信息，以及已经存在但未解决的线索。涉及钱和道具时写清此刻属于谁；没有证据就保留未知。信息可以作为背景已存在，但必须区分是谁知道。

不得把整段小说的事件清单或后续连续性备忘录塞进 ledger_in。首集内才完成的成交、反击、死亡、回家、救治，以及后续集才发生的收入、能力确认、态度变化，都不是起始时刻已经完成的事实；它们由计划节拍描述，再由各集 ledger_out 记录结果。若选的是倒叙开场，只能把该开场之前确实已发生的事情计入起始状态，不能同时混用另一开场候选的时间线。

独立方案审查须核对上述时间切点：引用 ledger_in 中的目标原句和输入中的计划或原文依据，指出将未来事件写成初始事实、错置持有者或让人物提前知情的问题。不要只因 ledger_in 提及某个名字就判断为泄漏，判断的是具体状态在这个时间点是否成立。
