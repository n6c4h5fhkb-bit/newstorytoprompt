# 实施说明

StoryForge Lite 是本地文本生产工具，完整目标包括 M0–M4。代码实现、固定响应测试、真实模型流程与真实视频效果分别记录，不以演示通过代替实际验收。

## 代码结构

| 目录 | 职责 |
| --- | --- |
| `platform/storyforge/runner/` | 小说编剧、导演、审查与续跑调度 |
| `platform/storyforge/packets/` | 独立调用的上下文白名单和输入版本 |
| `platform/storyforge/llm/` | Codex CLI 与可选 API、缓存、收据、有限重试 |
| `platform/storyforge/checks/` | 结构、引用、人物、状态、时长和审查回应检查 |
| `platform/storyforge/store/` | 文件真值、事务恢复、项目 Git 快照、SQLite 作业索引 |
| `platform/storyforge/cards/` | 审批、预算、故障与创作决定 |
| `platform/storyforge/refs/` | 参考资产选择及母子依赖 |
| `platform/storyforge/delivery/` | 最终 Prompt、资产清单与 ZIP 交付 |
| `platform/storyforge/ui/` | 本地四页界面，共用 CLI 服务 |
| `skills/` | 可编辑的角色方法、审查标准与格式 |
| `tests/` | 固定样例、失败注入、隔离 HTTP/CLI 和流程测试 |

阶段、输出结构和角色可见输入分别定义在 `platform/stages.yaml`、`platform/schemas.yaml` 和 `platform/packets.yaml`。

## 已实现的关键行为

- 小说按章段编号，摘要引用可追溯；关键时刻三版创作与独立选优，普通时刻一版。
- 首集须人工确认后锁定；后续集按结束状态与上一场顺序续写。
- 分集观众和故事审查在共享并发上限内并行，审查不接收作者推理。
- 每项 major/blocker 必须明确回应；改法建议不能成为新增剧情事实的依据。
- 人物常规母图与可拆卸道具分别提取，佩戴和持有用状态组合；显著换装等仍可使用子图。
- 美术定调、角色、场景、道具 Prompt 与最终逐镜视频 Prompt 一起交付。
- 超出自动修订次数时保留候选稿；Inbox 默认展示必须修复的问题，备注选填。
- 普通网页继续保留已选分集；故障重试同时保留停止阶段和分集范围。
- 版本变化不会由迟到输出覆盖；缓存和收据支持恢复，未知用量保持未知。
- 每个项目独立保存创作 Git 快照；根仓库只管理应用源码和可公开文档。

## 验证边界

固定样例检查了交付、独立上下文、故障修复、引用、缓存、预算、顺序锁定和模拟批量流程。针对最近的资产拆分、并行审查、网页继续范围和候选稿只读预览有定向回归通过记录。历史完整测试曾出现一项过时断言，随后已修正并单独复核；尚未把全部最新代码再次完整测试的结果记为通过。

当前真实首集已完成编剧审查并由用户批准锁定，导演阶段已完成美术方案和资产提取。资产 Prompt 尚未全部完成，最近一次因模型服务满载暂停；正式分镜和视频 Prompt 交付仍待完成。完整关闭条件见 [验收核对](requirements-audit.md)。

## 仓库与本地资料

根仓库采用明确的文件允许清单。`projects/`、运行目录、数据库、缓存、日志、截图、真实调用记录和原始文档备份不进入版本控制；历史记录仍留在本机。测试目录中的短文本是固定协议样例，不是用户导入的真实小说。

默认 `config.yaml` 只包含模型与运行参数，不保存登录信息。API 示例只引用环境变量名。Codex 登录仍由本机 CLI 管理。初始提交使用通用作者标识；远程同步只包含受版本控制的源码、固定样例和公开文档。
